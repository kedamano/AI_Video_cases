## 一、先选路线：视频模型 vs 代码渲染

做 AI 视频前最该决策的不是提示词，而是**用哪条技术路线**。两者不是替代关系，而是分工关系。

| 维度 | 视频模型路线 | 代码渲染路线 |
| --- | --- | --- |
| 代表 | Seedance、Veo、Sora、可灵 | HyperFrames、Remotion、Manim、three.js |
| 画面来源 | 模型直接生成每一帧像素 | 程序算出一帧，渲染器截图后拼装 |
| 可复现性 | 每次抽卡结果不同 | 同一份代码渲染 100 次结果一致 |
| 精确修改 | 改一个细节要重抽，容易连带变化 | 改一个数字即可（如标题左移 20px） |
| 擅长 | 写实、真人、复杂光影、自然运动 | 信息图、数据动画、手绘/水彩、板书、3D 图形 |
| 成本结构 | 按次/按秒计费，重抽成本高 | 本地算力，重渲几乎零边际成本 |

来源：空格《拆解 9 个方法，让 AI 写代码帮你做视频》（2026-10-20）

**代码渲染的本质**：写一个 `f(t)` 函数，给时间返回一张画面；渲染器从第 0 帧开始逐帧调用、逐帧截图，最后由 FFmpeg 拼成 MP4 并混音。所谓「不同风格」，只是这个函数交给了不同的绘图库。

**实践建议**：写实镜头用视频模型，片头/片尾/数据动效/字幕卡用代码渲染，两者在剪辑阶段合成。本仓库的《玻璃之后》走的是纯视频模型路线，但片头片尾完全可以换成代码渲染以降低成本。

## 二、生产流程：选题 → 脚本 → 风格

一套被验证过的资讯类视频工作流，三步框架（来源：陆三金 @threeaus）：

### 1. 选题

- **AI 只能粗选，精选必须靠人工。** 让 AI 一次定稿是典型踩坑点。
- 信息源集中在 X 与 Hacker News；评论区往往比正文更有价值。
- 好选题自带冲突：谁做了什么、和谁对立、为什么值得吵。

### 2. 脚本

- 交给 LLM 写初稿，但**必须人工确认后才允许进入制作**。
- 引入**对抗式审查子 agent**：专门挑逻辑漏洞、信息缺口、叙事断裂。等价于把最耗时的返工提前。
- 作者实测：一份脚本最多改了 6 次。**流程里最耗心力的从来不是生成，而是修改。**

### 3. 风格

- 把风格**固化**成可复用的 skill / 词块，而不是每次重新描述。
- 作者开源的 `creator-style-kit` 提供 18 套 9:16 竖屏风格，每套锁定字体、配色、动效、音效、构图。

### 素材先行

开工前把素材文件夹备齐，目的是**固定整体风格、减少生成阶段的不确定性**：

1. `.env`（脚本模型 key + TTS key，仅本地）
2. 背景音乐
3. 两张背景图（文字动画或画面铺不满时兜底）
4. 片尾 logo
5. 原始素材截图（作为 Agent 截图失败时的兜底）

## 三、提示词工程

### 1. 六要素结构（资讯类）

```text
① 选题与信息源：原始链接 + 多渠道搜集（X 评论区 / Reddit / HN）
② 脚本：要求有钩子、有爆点；指定模型撰写；挂一个对抗式审查 agent；人工通过后才出片
③ 风格：指定风格库，或直接描述字体/配色/音效/MG 动画
④ 素材：明确已有素材，缺失时要求 Agent 主动索取
⑤ 辅助工具：TTS、配乐、截图/录屏能力
⑥ 品牌：片尾 logo、水印、辨识元素
```

### 2. 三段式画面描述（3D / 图形类）

```text
主体是什么 → 画面里该有什么 → 不能出现什么
```

例：「主体是一条小船；画面里有海、小岛、几棵树；不要出现任何文字和字幕。」

### 3. 负面约束要写进正向 prompt

**实测**：`ImageGen` 没有 `negative_prompt` 参数，所有「不要」只能写进正向描述；`VideoGen` 虽有该参数，写在 prompt 末尾同样生效。

### 4. 风格必须收敛成固定词块

自由描述会让同一角色在不同镜头间漂移。**实测**做法是把风格压缩成一段可复制的常量词块（见本仓库 `CLEAN BEAUTY`），18 个镜头共用同一段，靠提示词而非参考图锁脸。

## 四、一致性控制

长片崩掉的地方通常不是单帧质量，而是**跨镜一致性**与**节奏**。

| 对象 | 手段 |
| --- | --- |
| 角色/面部 | 固定描述词块 + 统一的年龄/发型/服装字段；必要时用参考图锁脸 |
| 色调 | 全片共用同一段色彩描述（如「青灰冷调，低饱和」），后期再加统一 LUT |
| 时长/节奏 | **先定分镜时长表**，再让模型生成，最后按表硬切；不要让模型自由决定节奏 |
| 音画同步 | **先有音频，再做画面**：TTS 先出每句时间戳，再让画面元素对齐时间轴 |
| 首尾衔接 | 每个镜头的首帧与上一镜末帧在构图/光向上留出衔接余地 |

## 五、审片标准清单

自动化剪辑的瓶颈不在生成，而在**审片标准**——没有可复用的清单，Agent 就无法判断「这条能不能发」。（该判断来自 @mychangShushu 的评论，本仓库认同并落地为下列清单。）

发布前逐条过：

- [ ] **单帧信息密度**：一帧里文字是否超过 12 字？超过就拆镜或删。
- [ ] **前三秒钩子**：第一句是否说清「谁、做了什么、冲突在哪」，而不是先堆数字和时间线。
- [ ] **叙事主线**：是否只有一条主线？无关细节是否已删。
- [ ] **节奏**：最短镜头是否短于 1 秒（会闪）？最长镜头是否超过 3 秒（会拖）？
- [ ] **一致性**：脸、发型、服装、色调在 18 个镜头间是否统一？
- [ ] **声画匹配**：配音与画面切换是否对得上？有无莫名音效。
- [ ] **TTS 读错**：人名、专有名词、数字是否读错。
- [ ] **技术规格**：分辨率、帧率、码率、音轨是否全片一致。
- [ ] **首尾完整**：第一帧是否黑场/脏帧？最后一帧是否停在有效画面上。

## 六、工具选型

按任务选，不按星数选。（选型表综合三篇来源，星数为原文 2026-10-27 快照，仅作参考。）

| 任务 | 推荐 | 差异点 |
| --- | --- | --- |
| 从零用代码做视频/动效 | HyperFrames、Remotion | 生态最成熟；HyperFrames 门槛最低，模型写 HTML 最稳 |
| 需要 React 生态、批量模板 | Remotion | `interpolate` / `spring`，多场景拼接与逐词字幕最顺 |
| 编程教学、代码块动画 | Motion Canvas | 按时间顺序写剧本，自带代码块组件 |
| 数学/公式/板书 | Manim | 数学对象 + LaTeX 矢量路径，状态插值 |
| 手绘线条、插画分层 | rough.js + SVG `stroke-dashoffset` | 端点随机偏移叠线；虚线偏移从全长到 0 即「描线」 |
| 水彩质感 | p5.brush | 多边形边中点迭代 + 40 层 4.5% 不透明度叠加 |
| 3D 场景 | three.js / Blender MCP | three.js 靠镜头曲线驱动；Blender MCP 让 AI 直接操作 Blender |
| 地图路线动画 | map-motion | 先 TTS 时间戳，再把路线进度插值到每句 |
| 写实真人短片 | 视频模型（Seedance / Veo / Sora） | 本仓库路线 |
| 素材 + 音轨自动粗剪 | video-use | 逐词转录下刀；**局限：模型不看画面，纯文本逻辑剪辑** |
| 需要看到渲染帧再改 | cutloupe | `look` 命令把真实渲染帧送回模型 |
| 商业发布片高频局部修改 | huashu-motion | 浏览器内按 `C` 键，点击任意帧提意见，帧级修改 |
| 长文转手绘口播科普 | sweety-handdraw-video | 口播稿/分镜/插画一体化，帧级对齐 |

**选型原则**（来源：刘老板 @leo_xiaolei 的评估标准）：

1. 必须真的围绕视频/动效产出，而不是演示 demo；
2. 必须能被 Agent 调用与复现；
3. 必须有完整 README，否则无法验证真实价值。

> **反高星滤镜**：星数不代表生产力。刚建库、个位数 Star 的项目，往往在解决极具体的痛点。评估看「能否被 Agent 复现/改造」，不看热度。

## 七、本仓库实测复盘

以下是《玻璃之后》项目里撞过的墙，全部可复核。

### 1. 「真实感」提示词会把脸画脏

写了 `visible freckles` / `fine skin pores` / `real skin texture` / `no beauty retouch`，结果面部灰浊、油高光、颗粒叠满。

**结论**：纪实感不等于脏。想要干净质感，必须显式写 `flawless porcelain skin` / `matte finish with zero oily sheen` / `no freckles, no blemishes, no dirt`，并加 `clean image`。

### 2. 脏感不只存在于脸

第一轮只修 7 个面部特写，其余 11 镜仍然发闷。**结论**：灰阶与重颗粒是全片的，无脸镜头（水洼、手部、逆光剪影）同样要统一重出。

### 3. 并行生图会合并输出目录

`ImageGen` 并行多张时，即使每张传不同 `output_dir`，也会落到同一目录，文件名只按 prompt 前缀派生。

**结论**：单批 ≤3 张；每张用不同前置词（`Window profile:` / `Eye macro:`）避免前缀撞车；生成后按返回的 `localPath` 精确改名，不要靠文件名猜。

### 4. 图生视频不接受画幅参数

`VideoGen` 传 `aspect_ratio` 会报错。**结论**：图生视频的画幅由输入首帧决定，删掉该参数。

### 5. 时长必须由分镜表控制

18 段各 5 秒的素材，最终剪成 25 秒。**结论**：生成阶段不追求时长，拼装阶段按 `[2,1,2,1,1,2,…]` 逐段 trim，节奏才可控。

### 6. 音轨统一后置

视频阶段全部 `enable_audio=false`，音效在拼装阶段统一叠加。**结论**：多段素材各自带音轨，拼接点必然爆音；统一后置才能保证连续。

### 7. 大文件必须走 LFS

18 段原片 + 成片共约 370MB。**结论**：`git lfs track "*.mp4"`，clone 端必须 `git lfs pull`，否则拿到的是指针文件。
